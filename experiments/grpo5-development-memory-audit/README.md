# Read-only development memory audit

Fixed checkpoints: hands 5, 10, 20, 25 and 30 in each of the four selected parent-GRPO5 development games, eval_c86991deffcc. Missing future records stay pending; policy busts can legitimately omit cleanup turns. No model calls, FINAL sources, training, output rewriting or hidden engine facts are used.

`fetch_visible.py` uses the existing supported native get_completion span query. Exact original P/R remain private under ignored `raw/`. `audit.py` constructs its fact ledger exclusively from actual cleanup USER observations. Cached C/RL20 source byte hashes are checked against their existing development manifests; only the policy seat's cleanup prompts and exact generated update payloads are read. Prior scratchpad text is not treated as truth.

Format acceptance is separate from factual memory. Parent live spans establish emitted tool shape only until the final raw host acceptance is available. Cached runs provide host acceptance. The existing conservative parser accepts only full `hand N: board ...; stacks {...}` blocks; unsupported free prose is UNKNOWN, not automatically false. Parsed board/stack disagreements are reported with current/prior temporal scope. Useful-prior counts are verified blocks, not a semantic recall metric.

The initial bounded manual review covers eight parent notes at hands 5/10/20/25 in two games. All explicitly stated current board/stack values match visible cleanup facts. Five notes nevertheless mislabel the current player's SB/BB position; original inputs use literal seatN names, not static blind-position names. Minimal exact evidence stays in ignored position-disambiguation-evidence.json; the public aggregate includes only classifications, IDs and hashes. One own hole-card suit and one public hand-category claim are also wrong. One additional current-street claim is unsupported and one temporal phrase remains ambiguous. A useful prior publicly revealed card fact is verified in one hand25 note against the original hand24 cleanup USER observation. This is not a full factual-memory pass.

Cached C and RL20 have the same development seed set but different policy trajectories, observed inputs and note styles. Their descriptive checkpoint counts are not an identical-context causal comparison or proof of broad memory improvement. Current-state agreement does not establish prior-history correctness or strategy quality.
