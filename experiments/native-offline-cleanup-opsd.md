# Native offline OPSD memory repair: CPU contract

Status: preparation only. No probe, dataset mutation, training or permission claim. Parent approval required before each next resource stage.

Problem: OWN SFT10 emits malformed or excessive cleanup and loses prior facts. Long-memory contexts from our actual incumbent Arena requests expose that defect without fabricating scratchpads. Infrastructure success of the OWN one-update GRPO family does not establish poker quality.

Hypothesis: a frozen copy of OWN10, conditioned on a teacher-only concise factual retention hint, assigns a more useful distribution than the same model without the hint at authentic OWN10 continuation tokens. Native offline OPSD may transfer this conditional preference while preserving the student's original interface and complete historical transcript. This tests conditional distribution change, not imitation of RL20 outputs and not a claim that the contexts were sampled on-policy.

Targeted approach: data agent supplies at most32 decision-time cleanup contexts and verified source facts, whole-match split and existing holdout exclusion. Student/ref seed is ckpt_95bc5ed22ed8 (OWN10); both hinted/unhinted probes use that SAME immutable model/checkpoint/version. Contexts are off-policy incumbent-C histories, including authentic past assistant/tool messages; only the newly sampled unhinted reply is on-policy OWN10. No RL20 target, SFT quote adapter, synthetic reasoning, replacement memory or future/private fact. Preserve tools exactly as offered at collection; emitted arguments do not prove the offered schema.

## Record contract

Each record contains original runtime prompt items P and complete authentic unhinted OWN10 response items R (reasoning, assistant text and real function calls, in order). HintedTask.input = P + R. Set one HintSelection with rollout_prefix_len=len(P); append_to_previous_item at item_boundary=1 appends the hint to the first system message for the teacher only. Require P[0] is the actual system message. Store exact original request/response bytes and hashes, source match/hand/seat/span/time, split, source inference ID, sampled OWN10 checkpoint/version, tools hash, sampling config, token counts and finish reason. Hint is built from visible P facts only and separately hashed. env_params.tools carries actual exact schemas. There is no labeled output/reward, agent, environment, grader, custom_harness or in-run evaluation.

Critical boundary: every original past assistant/tool item stays within P, including prior reasoning and update results. Never select the first assistant item as a loss boundary. Only R is selected by the hint boundary. Local HintSelection validates item indexes, not the server's token loss mask; a managed first-batch token audit must demonstrate past assistant/tool tokens have zero selected loss and the complete new reply is selected, with teacher hint absent from student prompt. This is a mandatory verification gap, not proven by local serialization.

Native recipe: OPSDConfig(rollout_mode='offline'), samples_per_problem=1, n_inference_replicas=0, eval.mode='off', no eval datasets/components, enable_thinking=True. ModelConfig(checkpoint=OWN10) selects both actor and frozen reference according to installed SDK train.py documentation. Explicit cleanup reply cap10000 tokens including reasoning; context+reply limit must fit full unmodified history and teacher hint without truncation. Tokenize exact templates and fail closed on overflow; max_total_len must exceed the measured longest teacher transcript within catalog capacity. No automatic context shortening. Offline does not sample or call opponents. Approximately4 training GPUs is recipe guidance, not capacity proof.

## Authentic defective reply policy

Do not repair, shorten, replace, synthesize tool calls, or add a tool result after R. Invalid JSON argument strings, absent/wrong tools and contents over5000chars are authentic behaviors, not SFT labels. Preserve them in the probe denominator and separate valid/overlong/malformed/missing/wrong-tool cohorts. The local runtime HintedTask accepts these structural forms: FunctionCall.arguments is an unconstrained string and no application tool semantics are checked. Synthetic local audit proves only that fact; it does not establish remote admission or template support.

For proposed offline training, keep structurally renderable complete authentic replies, including semantic invalidity/overlong contents, ONLY if remote native tokenization and selected-loss audit succeed without repairs. Reverse-KL teacher conditioning may reduce probability of bad tokens where hinted teacher disagrees; inclusion is not supervised endorsement. But it does NOT guarantee every invalid sample receives a suppressing gradient or discovers missing correct outputs. This must be demonstrated by behavior probes, not assumed from the objective name. No semantic-success filter that silently erases the known failures. Record exclusions explicitly for transport failure, no response, unknown truncation, token-cap termination or structurally unrepresentable items; retain them in reported failure denominators but do not invent a completed transcript. Terminal malformed JSON strings can be retained if truly complete and renderable. Unknown tool names may require renderer tool-schema support; do not extend actual tool definitions to make them pass. If any defect cohort cannot render, STOP that cohort and escalate rather than silently train on a cleaned subset.
